# Task 6 — Report Definition

## What does the report represent?

A human-readable Markdown summary of a completed Week 3 multi-agent
discussion, produced from the unified analytics result computed by Task 5.
The report is the primary human-facing output of the analytics layer: it
presents opinion change, agreement, influence, and sentiment in a form that
a reviewer, mentor, or Week 5 dashboard can consume directly.

The report is not a data dump. It summarizes findings, interprets trends in
plain language, and explicitly notes where a metric could not be computed.
A reader who has never seen the underlying JSON should be able to read the
report end-to-end and understand what happened in the discussion, how the
agents' positions evolved, and what the analytics can and cannot claim.

---

## What is its format?

Markdown (`.md`). Chosen because:

- It is the format explicitly required by the Week 4 specification.
- It is trivially readable as plain text and cleanly rendered by any editor,
  browser, or dashboard.
- It supports tables, headings, and embedded images — the three presentation
  features the report needs.
- It requires no external tooling to view or diff.

---

## Two rendering paths

The report module provides two rendering paths that share the same section
renderers and produce compatible Markdown. Both are documented here because
Week 5 may consume either.

### Path 1 — Deterministic (default)

`render_report(analytics)` and `write_report(analytics, path)` produce a
fully rule-based report. Every number, every table, every finding, and every
trend interpretation is generated by Python from the analytics dict. The
output is byte-for-byte reproducible for a given input.

This is the default. It requires no LLM, no API key, no network access, and
no model download. It is the path that all existing callers use and the path
that the acceptance tests exercise.

### Path 2 — Agent-assisted (opt-in)

`write_agent_report(analytics, path, agent=...)` and
`generate_agent_report(discussion_path, path, agent=...)` run a
`ReportAgent` over the analytics dict to produce narrative sections, then
interleave those sections with the same deterministic tables. The agent
writes prose only; every number and every table in the final report still
comes from `report.py`.

The agent path adds two unnumbered bracketing sections — an Executive
Summary before the numbered sections and a Conclusion after Key Findings —
and replaces the deterministic Key Findings bullets with the agent's
findings. The numbered sections retain their numbers and their
deterministic tables.

The agent path is opt-in via the `--agent` CLI flag. It requires a
configured LLM provider. When the LLM call fails, the script logs the
failure and falls back to the deterministic report for that discussion, so
a transient provider error cannot abort a batch run.

Both paths produce the same core structure. A downstream consumer that
splits the report by heading can rely on the numbered section anchors
regardless of which path produced the file.

---

## What is its range / size?

The report is a single Markdown file. Its length scales with the discussion
and with the rendering path:

- **Deterministic:** a 4-agent, 4-round discussion produces roughly 6–10 KB
  of Markdown.
- **Agent-assisted:** the same discussion produces roughly 10–15 KB, because
  each metric section gains a narrative paragraph and the report gains the
  Executive Summary and Conclusion.

Neither path has a hard size cap. Length scales linearly with the number of
agents, rounds, and — in the agent path — the verbosity of the model.

---

## What does a higher-quality report look like?

A good report:

- Contains all eight numbered sections, even when a metric is empty.
- Presents each metric as a table plus a short interpretation.
- Uses hedged language for association-based findings.
- Notes limitations explicitly.
- Renders correctly in any Markdown viewer.
- (Agent path) Uses specific agent names and specific numeric values rather
  than generic statements, and preserves the "association, not causation"
  caveat for influence.

A poor report:

- Omits sections whose data is missing.
- Emits raw metric values without interpretation.
- Claims causation from influence scores.
- Breaks tables because a cell contains an unescaped `|` or newline.
- (Agent path) Invents numbers, conflates sentiment with stance, or
  paraphrases values differently from the underlying metrics.
